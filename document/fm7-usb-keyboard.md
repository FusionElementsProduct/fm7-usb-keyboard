## 1. 概要

FM-7実機キーボードユニット（34ピンフラットケーブル接続）を、Raspberry Pi Pico純正を用いてUSB HIDキーボード化する変換基板。FM-7の筐体内、または単体基板として組み込むことを想定する。

初期調査（fm7-keyboard-pico.md）からの主な変更点：

| 項目 | 初期調査（Plan A） | 本仕様 |
|---|---|---|
| Picoモジュール | 無印Pico、ソケット実装 | **純正Raspberry Pi Pico**、ソケット実装（変更なし） |
| SENSE線 | 7本（pin24=N/C想定） | **7本（SENSE0–6のみ使用）**。pin24=SENSE7は回路図上存在するがキー未接続（[キーマトリクス](./fm7-keymatrix.md)で確認済み） |
| LED | 非搭載 | **CAPS・かなの2灯を搭載**（INSERTは非搭載） |
| ファームウェア | arduino-pico + Keyboardライブラリ | **arduino-pico + Adafruit TinyUSB**（PlatformIO。[§5.1](#51-開発環境)） |

## 2. システム構成

```
FM-7キーボードユニット
   │ (34ピン・フラットケーブル)
   ▼
[J3] 34ピンボックスヘッダ
   │
   ├─ SCAN0-15 ──┐
   ├─ SENSE0-6 ──┤   Raspberry Pi Pico (RP2040)
   ├─ BREAK ─────┤   [J1][J2] 2×1x20 メスヘッダでソケット実装
   ├─ GND ───────┤
   └─ LED(CAPS/かな) ─ NMOSドライバ×2 ─┘
                                          │ USB (micro-B, Pico実装)
                                          ▼
                                      ホストPC（HIDキーボードとして認識）
```

## 3. ハードウェア仕様

### 3.1 Raspberry Pi Pico

- **純正 Raspberry Pi Pico（RP2040）を使用**。クローン・互換ボードは使用しない。
- 実装方法：基板に直付けせず、**2×1x20 2.54mmピッチ メスヘッダ（ソケット）**で着脱可能に実装する（[EasyEDAスキーマティック](#8-pcb実装状況)で確定済み）。
- 電源：USB Bus Power（VBUS 5V）のみ。外部電源コネクタは設けない。
- 動作電圧：3.3V系。FM-7キーボードマトリクスは受動部品（スイッチのみ。キーごとのダイオードは確認できていない、[§5.2](#52-usb-hid)参照）のため、Pico内部プルアップ（またはボード上プルアップ）で3.3V動作させる。レベルシフタは不要。

### 3.2 FM-7キーボードコネクタ（J3）

34ピン ボックスヘッダ（2列×17、2.54mmピッチ、IDC標準ピン配置）。

| ピン | 役割 | 本数 |
|---|---|---|
| 1–16 | SCAN0–15（出力） | 16 |
| 17–23 | SENSE0–6（入力、プルアップ） | 7 |
| 24 | SENSE7 — **未接続**（回路図上は存在するがキー未割当、[キーマトリクス](./fm7-keymatrix.md)参照） | – |
| 25 | BREAK（入力、プルアップ、CPU FIRQ相当） | 1 |
| 26–28 | GND | 3 |
| 29 | INSERT LED制御 — **本設計では未使用・未接続** | – |
| 30 | かなLED制御（SINK、0で点灯） | 1 |
| 31 | CAPS LED制御（SINK、0で点灯） | 1 |
| 32–34 | LED用 +5V | **3本とも結線** |

> **注記**: 実機マザーボード回路図（FM-7キーボード回路図.png）ではpin24はSENSE7（MB88401のR7）に結線されている。しかし[キーマトリクス対応表](./fm7-keymatrix.md)の解析により、SENSE7にキーが1つも接続されていないことが判明した。したがってpin24はGPIOに接続せず未結線とし、その分のGPIOをLED制御に充てる。

### 3.3 LED（CAPS・かな）

- **CAPS LOCK・かなロックの2灯を搭載**。INSERTは搭載しない（コネクタpin29は未接続のまま）。
- FM-7キーボード側のLEDは基板内蔵で、コネクタ経由の **SINK駆動（0=点灯）**、アノード側は+5V給電（コネクタpin32–34をPicoのVBUS(5V)に接続）。
  - **pin32/33/34は3本ともVBUSに結線する。** 実機マザーのCN6（FM-7キーボード回路図.png）も参考コンバータのMCP23S17版（キーボード・インターフェース.jpg、いずれも本リポジトリ未収録）も3本を束ねており、GND側(26/27/28)も同様に3本束ねるのが標準。資料からはキーボードユニット内部で32/33/34が共通なのかLEDごとの別アノードなのかが確定できず、**1本だけ結線するとLEDが点灯しない可能性**があるため、3本とも結線してリスクを消す（配線コストは200mil）
- RP2040のGPIOは3.3V系のため、GPIOを直接HIGHにしてOFFにしようとしても、5V給電されたLED側との電位差（約1.7V）で**微点灯する恐れがある**（初期調査で指摘済み）。
- **対策**：GPIOでLEDを直接駆動せず、**NMOSトランジスタ（2N7000等）によるオープンドレイン駆動**を各LEDに1個ずつ、計2個使用する。
  - GPIO HIGH → MOSFET ON → LED制御ピンをGNDにシンク → LED点灯
  - GPIO LOW → MOSFET OFF → LED制御ピンはハイインピーダンス → 消灯（10kΩプルアップ R5・R6 でちらつき対策、搭載済み）
  - ゲート-GPIO間に直列抵抗 100Ω（R1・R2、突入電流対策、搭載済み）
  - **NMOSドレインとコネクタピンの間に470Ωの電流制限抵抗を直列に入れること（必須）**。実機マザーボード回路図ではM143(74LS05)出力とCN6の間にR66/R67(470Ω)が入っており、キーボードユニット内のLEDには電流制限抵抗がない。

```
LED駆動回路（CAPS / かな 各1回路、計2回路）:

  GPxx ── 100Ω ──┤ Gate
                   │ 2N7000
             GND ──┤ Source
                   │
  CN6 pinYY ─ 470Ω ┤ Drain

  CN6 pin32 ─── +5V (VBUS)

  CAPS: GP26 → Q1 → 470Ω → CN6 pin31
  かな:  GP28 → Q2 → 470Ω → CN6 pin30
```

### 3.4 BREAK キー

- コネクタpin25。マトリクスと独立（FM-7実機ではCPUのFIRQ直結）。
- 入力・プルアップで読み取り、USB HID側は Pause（`0x48`）に割り当てる（[§5.5](#55-breakキー)）。

## 4. GPIO予算

Raspberry Pi Pico の実使用可能GPIOは26本（GP0–22, GP26–28）。GP23（SMPS mode select）・GP24（VBUS sense）・GP25（オンボードLED）は内部用途のためヘッダに出ていない。GP25はオンボードLEDの表示にのみ使う。

必要信号数：SCAN 16本 + SENSE 7本（SENSE0–6） + BREAK 1本 + LED 2本 = **26本 → ちょうど収まる**（pin24のSENSE7はキー未接続のため不要、予備GPIOなし）。

| 信号 | Pico GPIO | コネクタピン |
|---|---|---|
| SCAN0–15 | GP0–15 | 1–16 |
| SENSE0–6 | GP16–22 | 17–23 |
| （SENSE7 / pin24） | — | 24（キー未接続、未結線） |
| LED_CAPS | GP26 | 31（NMOS + 470Ω経由） |
| BREAK | GP27 | 25 |
| LED_KANA | GP28 | 30（NMOS + 470Ω経由） |
| INS表示（変換ファーム：Scroll Lock）／ステータス表示（診断ファーム） | GP25（オンボードLED） | — |

**予備GPIOなし。** INSERT LED（pin29）は未接続のため、INS状態はPicoのオンボードLEDで代用表示する。

## 5. ソフトウェア仕様

> **2026-09-23に実装済み。** 本節は実装（[src/](../src/)、[platformio.ini](../platformio.ini)）に合わせて改訂したもの。旧版はPico SDK + CMake・NKRO専用を前提にしていたが、いずれも実装と異なっていたため差し替えた。

### 5.1 開発環境

- **arduino-pico（Earle Philhowerコア）+ Adafruit TinyUSB**、ビルドはPlatformIO。
- 環境は3つ。

  | env | 内容 |
  |---|---|
  | `pico` | 変換ファーム・**6KRO（ブートプロトコル互換、既定）** |
  | `pico_nkro` | 変換ファーム・NKRO（21バイト＝modifier 1＋ビットマップ20、usage 0x00–0x9F） |
  | `pico_diag` | シリアル診断ファーム（USB HIDなし） |

### 5.2 USB HID

NKROディスクリプタは実装済みだが、**既定は6KROとする**。理由は2つ。

1. **fm7emulatorがブートプロトコルしか解釈しない。** fm7emulator.c（本リポジトリ未収録）の `find_key_in_report()` は `hid_keyboard_report_t`（8バイト・レポートIDなし・キー6個）を読み、`process_kbd_leds()` は `tuh_hid_set_report(..., report_id=0, ...)` で1バイト送る。NKRO専用にすると本来の用途で動かない。
2. **HIDインターフェースを2本同時に出すと二重入力になる。** 通常のOSはキーボードが2台あると解釈する。そのためビルド時にどちらか一方だけを選ぶ。

旧版にあった「FM-7キーボードはダイオード内蔵でファントムキー対策済み」という記述は**裏付けが取れていない**。母艦は74LS145×2でスキャンしMB88401のファームで曖昧さを解決しており、キーごとのブロッキングダイオードがある証拠は資料中にない。したがってNKROにしても2キーを超えた時点でゴースト抑止が必要で、`pico_nkro` は「6キー上限が邪魔なホスト向け」の選択肢であってロールオーバーの解決策ではない。**ダイオードの有無は `pico_diag` のゴーストテストで確定できる**（[§5.4](#54-診断ファームウェア)）。

**LED状態受信**（[src/fm7_usb.cpp](../src/fm7_usb.cpp) の `setReportCallback`、[src/main.cpp](../src/main.cpp) の `applyHostLeds()`）。デコードはfm7emulatorの送出内容に合わせる。

| Output Reportのビット | 意味 | 本機の割当 |
|---|---|---|
| bit0 Num Lock | fm7emulatorは**KANAをNumLockで送る** | FM7モード：`LED_KANA` (GP28) |
| bit1 Caps Lock | CAPS | `LED_CAPS` (GP26) |
| bit2 Scroll Lock | fm7emulatorはINSをScrollLockで送る | Picoのオンボード LED（GP25。コネクタpin29未接続の代用） |
| bit4 Kana | HID標準のKana | Windows／Macモード：`LED_KANA` (GP28) |

> 旧版は「Kana = Usage 0x05、NumLockは無視」としていたが、それでは fm7emulator のかなランプが点灯しない。そのため FM7 モードでは Num Lock を、Num Lock を本来の意味で使う Windows／Mac モードでは Kana ビットを、かなランプに割り当てる。

### 5.3 キーマトリクススキャン

[src/fm7_matrix.cpp](../src/fm7_matrix.cpp)。

- **オープンドレイン駆動**：待機はINPUT（ハイインピーダンス）、走査中のSCAN線のみOUTPUT LOW。待機をHIGHにすると、2キーが同じSENSE行を共有したときに駆動中の線とぶつかる。
- 整定待ち50µs／線。16本で約0.8ms、走査は1kHz強。SENSE7（pin24）は未接続なので読まない。
- **デバウンス**：同一読み値が4走査連続したら確定（約4ms）。
- **ゴースト検出**：2本のSCAN線が2ビット以上のSENSEを共有したら長方形＝曖昧。その間はマトリクス部分を直前の確定状態で凍結して幻のキーを送らない。BREAKはマトリクス外なので凍結しない。
- **ロールオーバー溢れ**：6KROでキー6個を超えたら全スロットを `0x01`（ErrorRollOver）で埋める。
- キー対応表は [src/fm7_hid_map.h](../src/fm7_hid_map.h)。Shift/CapsLockの面替えは行わず、**生のHID Usage IDをそのまま送る**（面の解釈はホスト側＝fm7emulatorの `fm7usbcode[]` が行う）。CTRL/SHIFT/GRAPHはmodifierバイトで送る。
- ホストモード：`CTRL+GRAPH+PF1/PF2/PF3` で FM7／Windows／Mac を切り替える（電源断後も保持、切替時にCAPS/KANAランプが1／2／3回点滅）。FM7モードはKANA＝International2(`0x88`)、Windows/MacモードはKANA＝GUI修飾キー（Winキー／⌘）。GRAPH+KANA・GRAPH+SPACEは FM7/Mac＝LANG1/LANG2、Windows＝半角/全角(`0x35`)。

### 5.4 診断ファームウェア

`pio run -e pico_diag -t upload` ＋ 115200bpsのシリアル。

- キーの押下・解放ごとに `scan` / `sense` / キー名 / HID Usage を出力。**仕様書の表にない位置が押されたら `UNDOCUMENTED POSITION` と表示する**ので、[キーマトリクス対応表](./fm7-keymatrix.md)の検証がそのままできる。
- `d` でマトリクス全体をグリッド表示、`h` でヘルプ。
- `g` でゴーストテストの手順を表示。**長方形を作る3キー（例：Q・W・A）を同時に押して `GHOSTING DETECTED` が出れば、キーごとのダイオードが無い＝真のNKROは不可能**と確定する。

### 5.5 BREAKキー

- コネクタpin25の独立ピン。マトリクス外なのでゴーストの影響を受けない。HID Usage `0x48`（Pause）を送る（[§3.4](#34-break-キー)参照）。

### 5.6 テーブルの整合性検査

`python3 tools/check_keymap.py`（本リポジトリ未収録）で [src/fm7_hid_map.h](../src/fm7_hid_map.h) と [src/fm7_key_names.h](../src/fm7_key_names.h) を [fm7-keymatrix.md](./fm7-keymatrix.md) の表と112箇所突き合わせる。手書き転記のtypo対策なので、どちらかを編集したら必ず実行すること。

## 6. PCB仕様（現行スキーマティック/PCB作業ベース）

- 基板サイズ：**53.34 × 97.79 mm（2100×3850mil）**。2026-09-23に抵抗を1/4W品へ統一して短縮後、四隅のM3ネジ穴の縁距離を確保するため下端を延長。さらに同日、**J3（34Pコネクタ）の本体が基板左端から1.21mm飛び出していた**ため左端を100mil（2.54mm）拡幅し、**下側ネジ頭とJ3本体の干渉**を解消するため下端を50mil（1.27mm）延長した（変遷: 90.2 → 125.7 → 110.0 → 92.7 → 96.5 → 97.79mm、幅 50.8 → 53.34mm）
- **J3のクリアランス根拠**：J3（Sullins SBH11-NBPC-D17-ST-BK）の本体外形は 1995.27 × 358.66 mil ＝ **50.68 × 9.11 mm** で、**旧基板幅50.80mmとほぼ同寸**だった。そのうえJ3中心(x=1350mil)が旧基板中心(x=1400mil)から50mil左にずれていたため左だけが飛び出していた。中心合わせだけでは左右余裕が0.06mmにしかならないので拡幅が必須。現在は**左右とも1.33mm**で対称
- 基板外形：四隅を **R3.1mm（122mil）で角丸**。各コーナー円弧の中心は取付穴の中心と一致させてあるため、穴の周囲の残り幅が全方向で均一（1.5mm）になる。実装はEasyEDAのArc API（beta版で実際には図形が生成されなかった）を使わず、1コーナーあたり8分割の微小直線で構成（理論円弧との誤差0.015mm）。2026-09-23に36本のTRACKを単一の閉じたBoard Outlineへ変換し、外形なし警告を解消。出力画面で50.800×96.520mm、DRC 0件を確認（2026-09-23の拡幅後は **53.340×97.790mm**、DRC 0件）
- 取付穴：**M3用バカ穴 φ3.2mm（126mil）非メッキ（NPTH）・ランド無し × 4**、四隅に配置（外形から3.1mm内側／中心座標 **x=422・2278、y=28・-3578 mil**）。穴縁から基板端まで1.5mm、銅箔は穴中心から100mil以上離してある
- シルク（表面）：**基板右端の空きスペースに90°回転（下から上に読む向き）で4列縦配置**（いずれも y=-1350 mil 中心）
  - `FUSION ELEMENTS` — ブランド名。40mil・全大文字（x=2220・y=-1525）
  - `FM-7 Keyboard to USB Converter Type RPPico` — 製品名。45mil（x=2145・y=-1360）
  - `FM7USBKB-001` — ボード名／プロダクトNo。36mil（x=2220・y=-1155）
  - `Rev 0.5   2026-09-23` — 版数と日付。36mil（x=2285・y=-1375）
- 層数：2層
- 主要部品：
  - J1・J2：Picoソケット（2×1x20 2.54mmメスヘッダ）
  - J3：FM-7キーボード用34ピンボックスヘッダ
  - Q1・Q2：NMOSトランジスタ（LED駆動、CAPS用・かな用、2N7000_C9114、TO-92）
  - R1・R2：MOSFETゲート直列抵抗（100Ω × 2、PCF14JT100R / LCSC C2587286）
  - R3・R4：LED電流制限抵抗（470Ω × 2、必須、PCF14JT470R / LCSC C2585244）
  - R5・R6：LEDプルアップ抵抗（10kΩ × 2、+5V(VBUS)へ、PCF14JT10K0 / LCSC C2587295）
  - 抵抗6本は**同一シリーズ（PCF14JT、1/4W炭素皮膜、本体φ2.3×6.0mm、ピッチ10.00mm、穴径0.6mm）で統一**。以前は2W/1W/0.5Wの3種が混在してシルクの大きさがバラバラだったが、実際の消費電力は最大でもR3/R4の約19mW（R1/R2はゲート容量のみで定常電流ゼロ、R5/R6は約2.5mW）で1/4Wに十分な余裕があるため統一した。BOMも3行→1シリーズに整理される
- 実装方式：全THT（表面実装部品なし）

  - **ベタGND**：表裏ともGNDポリゴン（外形から20mil内側、角丸R102mil、solid塗り、優先度1、境界線幅10mil）。**スティッチングビア62個**を250mil格子で配置（全パッド・非GND配線・既存ビアに対するクリアランスを満たす位置のみ）。ビア総数94個
  - 検証：**EasyEDAのDRCは0件（エラー・警告とも無し）**。加えて自前の幾何チェック（線間・線対パッド・ビア対線/パッド/ビア）と、レイヤーを区別した連結成分チェックでも違反0・全34ネット連結を確認
  - 経緯メモ：配線はEasyEDAの自動配線ではなく、10mil格子のA*迷路探索で経路生成し、パッド・ビアのクリアランス制約を与えて生成したもの。過去に残っていた「+5Vの接続警告」等は、**ビアをトラックより後に作成するとEasyEDAが層間接続を認識しない**ことが原因と判明し、ビアを先に作る順序に変更して解消した
  - 配線整理（2026-09-23）：遠回りの原因は探索コストではなく**ネットを流す順序**だった。バス（SCAN/SENSE）を先に流すとLED段の局所ネットが押し出され、$1N289が最短経路の3.84倍（2690mil）になっていた。**局所ネット優先**の順序（Q1/Q2ゲート → ドレイン → LED_CAPS/KANA → SCAN → SENSE → BREAK → 電源）に変更し、VIACOST=45 / TURN=12 / GRAIN=1.4 で再生成。最悪の遠回り比が **3.84倍 → 1.95倍**、総延長 86421→84784mil、線分 176→167本に改善（ビアは30→32個とほぼ同数）。ビアコストを70まで上げると逆に総延長が113756milへ発散するため、この付近が最良点
  - 注意：一括削除では**EasyEDAが内部で分割した断片が削除リストから漏れる**ことがある（今回3本残存）。削除後は必ず「生成したはずの線分集合に含まれない線分」を突き合わせて残骸を掃除する
